I looked at how the web app builds and what the landing page needs. The good news is that the marketing pages (`/`, `/pricing`, `/whats-new`, `/privacy`, `/terms`, `/support`) are all static UI. They don't need Supabase, the database or any keys, and the voice clips are already files in `apps/web/public/voice`.

There is one catch. `apps/web/next.config.mjs` runs `deploy-checks.mjs`, which **stops a Vercel production build** unless two variables are set: `REVENUECAT_WEBHOOK_SECRET` and a `DATABASE_URL` that doesn't point at localhost. For a UI-only demo you can satisfy it with placeholder values.

## Steps

**1. Push your branch to GitHub.** You run the git commands yourself (repo rule).

**2. Import the repo on Vercel.** Go to vercel.com → **Add New → Project**, pick the repo, then:
- **Root Directory:** `apps/web` (this is the important setting)
- **Framework:** Next.js (detected automatically)
- **Build and Install commands:** leave the defaults. Vercel sees the npm workspaces and installs from the repo root. `prisma generate` runs on install and doesn't need a database.
- **Node version:** Vercel uses 22.x on its own because of `engines` in `apps/web/package.json`.

**3. Add two environment variables** (Production) before the first deploy:

| Name | Value |
| --- | --- |
| `REVENUECAT_WEBHOOK_SECRET` | the output of `openssl rand -hex 32` |
| `DATABASE_URL` | `postgresql://demo:demo@db.invalid:5432/postgres` (a placeholder that only passes the build check) |

Leave everything else unset. Supabase, PostHog, GA and RevenueCat all switch themselves off when their variables are missing.

**4. Deploy.** Vercel deploys the **production branch** (`main` by default). If the landing page you want to show is only on `feat/v2-social`, either:
- merge it to `main` first, or
- change **Settings → Git → Production Branch**, or
- deploy from your machine: run `npx vercel --prod` from the repo root, after linking with `npx vercel link` and setting Root Directory to `apps/web` in the project settings.

**5. Share the `https://<project>.vercel.app` link** in the hackathon channel.

## Things to know

- **Use the production URL, not a preview one.** Preview links have Vercel Authentication turned on by default, so anyone opening one hits a Vercel login. You could turn that off under **Settings → Deployment Protection**, but the production URL is the simpler route.
- **Some parts won't work, by design:** the waitlist and contact forms will show an error, and `/admin` and `/api/*` won't function, because there's no database. The cron in `vercel.json` will run daily and just be refused, which is harmless.
- **To check the build locally first,** run `npm run web:build`.
- `AGENTS.md` says this play is localhost-only. A UI-only showcase on Vercel doesn't change that for the app or the backend, but you may want to add a line to `docs/memory/` noting the demo deployment.
