Now where `micRefused` comes from:

The app shows that line whenever `voice.refused` is true. The catch is that the code reports "refused" in two different situations, and only one of them means you said no.

**Where it comes from**

`components/pet/TalkControls.tsx:203` shows the note when `micRefused` is true. That value comes from `useVoice().refused`, which is set from `listenPermission()` in `lib/speech.ts:54`:

```ts
export async function listenPermission(): Promise<ListenPermission> {
	const speech = recognizer()
	if (!speech) return 'refused'          // ← native module not in this build
	try {
		return permissionOf(await speech.getPermissionsAsync())
	} catch {
		return 'refused'                   // ← any error
	}
}
```

**So on your simulator it's one of these two:**

1. **The build has no speech-recognition native module (most likely).** `expo-speech-recognition` was added in `74562df` ("talk to your pet by voice"). If the dev client on the simulator was built before that commit, or from a checkout without it, `requireOptionalNativeModule('ExpoSpeechRecognition')` returns `null`. The app then calls that "refused", even though you were never asked. This worktree has no `ios/` folder, so the simulator app was built somewhere else, possibly from older code. If this is the cause, rebuild the dev client: `npx expo run:ios` from `apps/mobile`. A JS reload won't fix it because the change is native.
2. **Permission really was denied on that simulator.** If you tapped "Don't Allow" on the microphone or speech prompt earlier, `canAskAgain` is false and the note is correct. To reset it, go to Settings → Kinpaw → turn on Microphone and Speech Recognition, or run `xcrun simctl privacy booted reset all <bundle-id>`.

To tell which one it is: if the simulator's Settings → Kinpaw page has no Microphone or Speech Recognition toggles, it's cause 1.

This isn't caused by the app. It's how Loom handles audio from your Mac. I can't see your Loom settings, so here are the likely causes, most common first:

1. **Computer audio is off in Loom.** Loom records only your microphone unless you turn on system audio. In the Loom desktop app, before you start, open the recording menu and turn on **Record computer audio** (in some versions it's under Settings → Recording → "Use system audio"). This is the usual reason.

2. **Loom isn't allowed to capture system audio.** On recent macOS versions, open System Settings → Privacy & Security → **Screen & System Audio Recording**. Loom must be listed and turned on. If you change it, quit and reopen Loom.

3. **The Simulator sends its sound somewhere else.** In the Simulator menu bar, open **I/O → Audio Output** and pick **System default** (or the same device your Mac plays through). If it's set to a particular device, Loom may miss it.

4. **The sound is muted in the simulated iPhone.** Check that its silent switch is off (**I/O → Ringer**, or **⌘⇧M** in recent Simulator versions) and that its volume is up. iOS stays quiet when the ringer is silenced, so you'd hear nothing even before Loom.

A quick check: start a short Loom, play a YouTube video in your browser, and stop. If the browser sound is missing too, the cause is 1 or 2. If the browser is recorded but the Simulator isn't, it's 3 or 4.

If it still won't work, you can record the demo on a real iPhone using Control Center's screen recording. Long-press the button and turn the microphone on if you also want your voice.
