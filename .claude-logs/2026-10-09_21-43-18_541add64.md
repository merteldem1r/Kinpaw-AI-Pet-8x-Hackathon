## Top 5 findings

Nothing is rated Critical today, because nothing is deployed and RevenueCat is unconfigured. The first three become Critical the day the web app takes public traffic.

1. **ARCH-01: open advisories with nothing watching.** `npm audit` reports 75 (1 critical, 56 high), 47 of them in the production tree. `sharp@0.35.4` has a high-severity one and decodes anonymous uploads on the public photo route before the format check runs. CI never runs an audit and there is no Dependabot. I did not verify exploitability.
2. **ARCH-02: the RevenueCat webhook is unvalidated and unordered.** The body is cast, not parsed, and no event id or timestamp is read. A late `EXPIRATION` after a `RENEWAL` sets a paying customer to `free`, and a retry double-counts the purchase in first-party analytics.
3. **ARCH-03: no rate limiting on any route.** The photo reader's limits key on a caller-chosen install id and the first `x-forwarded-for` hop, so one script can use up the app-wide daily photo cap.
4. **ARCH-04: the waitlist enrols any address with `marketing_consent: true`.** There is no confirmation step, so anyone can subscribe a third party.
5. **ARCH-05: no end-to-end tests.** Only 1 of 28 screens is rendered in a test, and coverage is not measured. The parts are tested; the assembled sign-in, create, save, care and talk path is not.

ARCH-06 is close behind: the release path (EAS, Vercel, hosted Supabase, the migration deploy workflow) has never run, and `app.json` still holds `REPLACE_…` placeholders.

1. **Patch and gate dependencies:** `npm update sharp next`, add `npm audit --omit=dev --audit-level=high` to CI, and add Dependabot. Under a day.
2. **Harden the webhook:** a Zod schema, a processed-event-id table, and ignore events older than the last one applied. One to three days, and it is the money path.
3. **Fix the workspace boundary defects:**
